# 原版行為規格

這份文件記錄我們對參考遊戲（同類型的回合制戰略手遊）**可觀察行為**的了解：
在什麼輸入下，玩家會看到什麼結果。它描述的是「原版表現如何」，不是「原版的程式
碼長什麼樣」 —— 這裡沒有、也不應該出現任何原版的原始碼、資源或資料表內容。

本專案的實作是依照這份規格獨立設計的；規格與實作之間的對應寫在每一節的
「本專案」一欄。

## 來源與標記

| 來源代碼 | 意思 |
|---|---|
| 觀察 | 維護者實際遊玩原版所觀察到的行為 |
| 說明 | 原版遊戲內的說明文字（未加密的文字資源），此處只轉述意思，不引用原文 |

| 標記 | 意思 |
|---|---|
| ✅ | 已確認（多次觀察一致，或觀察與說明文字互相印證） |
| 🟡 | 有力推測，尚未以控制實驗驗證 |
| ❓ | **UNKNOWN BEHAVIOR** —— 證據不足，本專案的做法是近似值 |

不使用的來源：原版加密資料檔的解密內容、反組譯或反編譯的程式碼。

## 1. 戰役的勝利條件

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 每一關的勝利條件是「攻佔指定城市」或「堅守指定城市」其中之一 | 觀察 | ✅ |

### 本專案

- `ObjectiveType.CAPTURE_PROVINCES`：指定的省份全部歸玩家時勝利。
- `ObjectiveType.HOLD_PROVINCES`：到了指定回合時，指定省份仍全部在玩家手上即勝利。
- 另有 `ELIMINATE_NATION`、`SURVIVE_TURNS`、`CONTROL_COUNT` 三種目標，是本專案
  自己的擴充，原版沒有對應。
- 實作：`game/Session.kt` 的 `objectiveProgress`、`isObjectiveMet`、`evaluateOutcome`。
- 測試：`SessionTest` 的 ``objectives drive victory``。

### UNKNOWN BEHAVIOR

1. **超過回合上限時的結果。** 本專案判定為失敗（`turnLimit`）。
   原版可能是失敗，也可能只是拿不到星等。
   *實驗*：在原版任一關刻意拖過回合上限，記錄是結束關卡還是繼續進行。
2. **「堅守」的判定時點。** 是「到了第 N 回合那一刻仍持有」，還是「從開局到第 N
   回合之間一次都不能丟」？本專案採前者。
   *實驗*：在堅守關卡中途讓城市失守再奪回，看最後是否仍判定勝利。
3. **戰役中丟掉自己的首都是否直接失敗。** 本專案不會；只有失去最後一座城才出局
   （見第 3 節）。

## 2. 征服模式的勝利條件

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 勝利條件是攻下**所有敵國**的城市 | 觀察 | ✅ |
| 盟國與中立國的城市不在勝利條件之內 | 觀察 | ✅ |
| 可以對中立國宣戰，被宣戰的中立國從此成為敵國 | 說明 | ✅ |
| 敵國被 AI 盟軍攻下最後一座城而投降，效果跟玩家自己攻下一樣 | 觀察 | ✅ |
| 回合數超過該劇本的上限仍未勝利，判負 | 觀察 | ✅ |

### 規格

```text
enemies(P) = 與玩家 P 分屬敵對陣營的國家 ∪ 目前與 P 交戰中的國家
勝利 ⇔ enemies(P) 不為空，且 enemies(P) 中每一國都已投降（見第 3 節）
失敗 ⇔ 回合數 > 回合上限，且尚未勝利；或玩家自己投降
```

敵國失去最後一座城就投降，所以「所有敵國都投降」與「所有敵國的城市都在我方
陣營手上」是同一件事。

### 本專案

- 實作：`Session.conquestEnemiesOf`、`Session.evaluateOutcome`。
- 舊版規則「控制世界八成省份」已移除：它會逼玩家去打盟國與中立國。
- 回合上限：劇本檔的 `turnLimit`，由 `tools/genworld.py` 的 `write_conquest(turn_limit=…)`
  寫入；判負在 `Session.evaluateOutcome`。
- 測試：`SessionTest` 的 ``conquest is won without touching neutrals``、
  ``a neutral you declared war on has to be conquered too``、
  ``nobody to fight means no conquest victory``、
  ``a conquest still undecided past its turn limit is lost``。

### UNKNOWN BEHAVIOR

1. **還沒到參戰回合的敵對陣營國家算不算敵國。** 例如 1939 年的美國要到第 6 回合
   才參戰。本專案**把它算進去**（陣營是敵對的就算）。原版的結果不明，但這個情況
   在正常遊玩下幾乎不可能出現（要在參戰回合之前打垮所有已參戰的敵國，實際上
   只有作弊才做得到），不值得為它設計實驗；維持保守的做法。
2. **玩家選擇的是沒有陣營的國家，而且誰都沒宣戰。** 本專案的敵國集合是空的，
   所以不會勝利，玩家必須先宣戰。原版在這種情況下的行為未觀察。
3. ~~盟軍攻下敵國最後一座城~~ —— 已確認，見上表：效果跟玩家自己攻下一樣。
4. **各年份征服的回合上限數值。** 規則（超過判負）已確認，數值未知；
   目前劇本檔寫的是 0（不設限）。

## 3. 投降

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 一個國家的所有城市都被攻下之後，它立刻投降 | 觀察 | ✅ |
| 投降國剩下的所有部隊立刻消失 | 觀察 | ✅ |
| 投降國最後那座城市對應的領土歸攻下它的一方 | 觀察 | ✅ |

### 規格

```text
觸發：國家 N 的某座城被國家 C 攻下，且 N 因此一座城都不剩
效果：
  1. N 的所有部隊移除（不論在陸上、海上、或他國境內）
  2. N 名下剩餘的所有省份改歸 C
  3. N 退出戰局（不再有回合）
邊界：
  N 還有任何一座城 → 不投降，部隊與領土都不動
```

### 本專案

- 實作：`Session.captureProvince` → `Session.surrender`；`Session.ownsAnyCity`。
- 事件：`event_nation_surrendered`（「%1$s 向 %2$s 投降」）。
- 測試：`SessionTest` 的
  ``losing the last city is a surrender - units vanish, leftover land goes to the captor``、
  ``losing one of several cities is not a surrender``。
- 沒有城市、只剩部隊的國家（例如只有遠征軍的劇本勢力）不會因為這條規則出局；
  它們沿用舊規則：沒有任何省份也沒有任何部隊時才消失。

### UNKNOWN BEHAVIOR

1. **AI 對 AI 是否同樣適用。** 已確認攻方是玩家的 AI 盟軍時同樣投降（第 2 節）；
   攻守雙方都跟玩家無關的情況未直接觀察，本專案一視同仁，🟡。
2. **「領土」的範圍。** 原版的領土是城市轄下的格子；本專案的單位是省份，一省
   對應一座城。兩者在「最後一座城的領土歸攻方」這一點上結果相同。若原版還有不
   屬於任何城市的格子，那些格子投降後歸誰未知；本專案把投降國名下的所有省份都
   交給攻方。
3. **投降國的運輸艦上載著他國部隊時。** 本專案沿用「載具沉沒、乘客一起沉」的
   既有規則。原版未觀察。

## 4. 回合順序

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 開新局時由玩家先行動，AI 在玩家結束回合之後才行動 | 觀察 | ✅ |

### 規格

```text
每一輪：玩家 → 其他國家依序 → 回合數 +1 → 玩家 → …
第 1 回合開局時，任何 AI 都還沒有行動過。
```

### 本專案

- `Session` 建立時把玩家排在國家清單的第一位，其餘國家維持劇本檔的順序
  （依國力排），所以一輪總是從玩家開始。
- 國家 id 因此跟著玩家改變，存檔格式版本升到 2，舊版存檔視為過時。
- 測試：`SessionTest` 的 ``a new game starts on the player's turn, before any AI moves``。

### UNKNOWN BEHAVIOR

1. **AI 國家之間的先後順序。** 本專案依國力由強到弱。原版未觀察。

## 5. 佔領城市

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 城市沒有守軍、而且城市的 HP（城防）是 0，才能被佔領 | 觀察 | ✅ |

### 規格

```text
敵方或無主的城市 C，城防 hp(C)：
  hp(C) > 0  → C 對敵方是關著的：走不進、穿不過、空降落不下
               （可以從相鄰或射程內攻擊它的城防）
  hp(C) = 0 且 C 裡沒有部隊 → 第一支走進去的陸軍（能佔領的兵種）立刻拿下整省
```

### 本專案

- 實作：`Session.isCityShutTo`（走路、上岸、空降共用），`Orders.tryCapture`（進城即佔領）。
- 原本的「站在還有城防的空城裡，每回合削 50 點」圍城機制已移除：它讓部隊站在
  城裡、旗子卻還是對方的，跟「城防歸零才佔領」的規則看起來互相矛盾。
- 測試：`SessionTest` 的
  ``a city with defence left is shut until it is worn down, then taken by walking in``、
  ``nobody passes through a city that still has its defence``。

### UNKNOWN BEHAVIOR

1. **打光城防的那一擊是否同時佔領。** 本專案要另外有部隊走進去；原版是否在城防
   歸零、城裡沒人的那一刻由攻擊方直接佔領，未確認。

## 6. 待研究

以下行為會影響後續的實作，但目前沒有足夠證據，先列出來：

- 傷害公式與隨機範圍（最小攻擊到最大攻擊之間的分佈、取整時點）
- 編隊、等級對攻擊與生命值的影響
- 城市與部隊同格時的傷害分攤
- 經濟：每回合收入的計算方式與時點

每一項都應該先在原版上做控制實驗（固定兵種、地形、編隊，重複攻擊並記錄結果），
把輸入與輸出寫進這份文件，再決定本專案的實作。
