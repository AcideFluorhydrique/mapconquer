# 原版行為規格

這份文件記錄我們對參考遊戲（同類型的回合制戰略手遊）**可觀察行為**的了解：
在什麼輸入下，玩家會看到什麼結果。它描述的是「原版表現如何」，不是「原版的程式
碼長什麼樣」 —— 這裡沒有、也不應該出現任何原版的原始碼、資源或資料表內容。

本專案的實作是依照這份規格獨立設計的；規格與實作之間的對應寫在每一節的
「本專案」一欄。

## 來源與標記

| 來源代碼 | 意思 |
|---|---|
| 觀察 | 維護者實際遊玩原版所觀察到的行為 |
| 說明 | 原版遊戲內的說明文字（未加密的文字資源），此處只轉述意思，不引用原文 |
| 逆向 | 維護者對原版原生程式庫所做的靜態分析（反組譯），此處只記錄推導出的規則與數學關係 |
| 資料 | 維護者從原版資料表讀出的數值，此處只記錄作為行為規格所需的數字 |

| 標記 | 意思 |
|---|---|
| ✅ | 已確認（多次觀察一致，或觀察與說明文字互相印證） |
| 🟡 | 有力推測，尚未以控制實驗驗證 |
| ❓ | **UNKNOWN BEHAVIOR** —— 證據不足，本專案的做法是近似值 |

「逆向」與「資料」兩種來源自 2026-09-27 起使用（維護者的決定）。使用方式：
先把原版的程式行為整理成規則與數字，寫進這份文件，再依規則獨立實作；這份文件與
本專案的原始碼都不包含原版的程式碼、資料檔或資源。原版的規則是否採用逐項決定 ——
本專案有原版沒有的機制（補給線、斷補給會掉血），衝突時以本專案的設計為準，並在
各節的「本專案」一欄註明。

## 1. 戰役的勝利條件

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 每一關的勝利條件是「攻佔指定城市」或「堅守指定城市」其中之一 | 觀察 | ✅ |

### 本專案

- `ObjectiveType.CAPTURE_PROVINCES`：指定的省份全部歸玩家時勝利。
- `ObjectiveType.HOLD_PROVINCES`：到了指定回合時，指定省份仍全部在玩家手上即勝利。
- 另有 `ELIMINATE_NATION`、`SURVIVE_TURNS`、`CONTROL_COUNT` 三種目標，是本專案
  自己的擴充，原版沒有對應。
- 實作：`game/Session.kt` 的 `objectiveProgress`、`isObjectiveMet`、`evaluateOutcome`。
- 測試：`SessionTest` 的 ``objectives drive victory``。

### UNKNOWN BEHAVIOR

1. **超過回合上限時的結果。** 本專案判定為失敗（`turnLimit`）。
   原版可能是失敗，也可能只是拿不到星等。
   *實驗*：在原版任一關刻意拖過回合上限，記錄是結束關卡還是繼續進行。
2. **「堅守」的判定時點。** 是「到了第 N 回合那一刻仍持有」，還是「從開局到第 N
   回合之間一次都不能丟」？本專案採前者。
   *實驗*：在堅守關卡中途讓城市失守再奪回，看最後是否仍判定勝利。
3. **戰役中丟掉自己的首都是否直接失敗。** 本專案不會；只有失去最後一座城才出局
   （見第 3 節）。

## 2. 征服模式的勝利條件

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 勝利條件是攻下**所有敵國**的城市 | 觀察 | ✅ |
| 盟國與中立國的城市不在勝利條件之內 | 觀察 | ✅ |
| 可以對中立國宣戰，被宣戰的中立國從此成為敵國 | 說明 | ✅ |
| 敵國被 AI 盟軍攻下最後一座城而投降，效果跟玩家自己攻下一樣 | 觀察 | ✅ |
| 回合數超過該劇本的上限仍未勝利，判負 | 觀察 | ✅ |

### 規格

```text
enemies(P) = 與玩家 P 分屬敵對陣營的國家 ∪ 目前與 P 交戰中的國家
勝利 ⇔ enemies(P) 不為空，且 enemies(P) 中每一國都已投降（見第 3 節）
失敗 ⇔ 回合數 > 回合上限，且尚未勝利；或玩家自己投降
```

敵國失去最後一座城就投降，所以「所有敵國都投降」與「所有敵國的城市都在我方
陣營手上」是同一件事。

### 本專案

- 實作：`Session.conquestEnemiesOf`、`Session.evaluateOutcome`。
- 舊版規則「控制世界八成省份」已移除：它會逼玩家去打盟國與中立國。
- 回合上限：劇本檔的 `turnLimit`，由 `tools/genworld.py` 的 `write_conquest(turn_limit=…)`
  寫入；判負在 `Session.evaluateOutcome`。
- 測試：`SessionTest` 的 ``conquest is won without touching neutrals``、
  ``a neutral you declared war on has to be conquered too``、
  ``nobody to fight means no conquest victory``、
  ``a conquest still undecided past its turn limit is lost``。

### UNKNOWN BEHAVIOR

1. **還沒到參戰回合的敵對陣營國家算不算敵國。** 例如 1939 年的美國要到第 6 回合
   才參戰。本專案**把它算進去**（陣營是敵對的就算）。原版的結果不明，但這個情況
   在正常遊玩下幾乎不可能出現（要在參戰回合之前打垮所有已參戰的敵國，實際上
   只有作弊才做得到），不值得為它設計實驗；維持保守的做法。
2. **玩家選擇的是沒有陣營的國家，而且誰都沒宣戰。** 本專案的敵國集合是空的，
   所以不會勝利，玩家必須先宣戰。原版在這種情況下的行為未觀察。
3. ~~盟軍攻下敵國最後一座城~~ —— 已確認，見上表：效果跟玩家自己攻下一樣。
4. **各年份征服的回合上限數值。** 規則（超過判負）已確認，原版的數值未知。
   本專案四個年份一律 200 回合（`places.CONQUEST_TURN_LIMIT`），這是自訂的值：
   夠從一個國家打到全世界，又不會讓一局無限拖下去。

## 3. 投降

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 一個國家的所有城市都被攻下之後，它立刻投降 | 觀察 | ✅ |
| 投降國剩下的所有部隊立刻消失 | 觀察 | ✅ |
| 投降國最後那座城市對應的領土歸攻下它的一方 | 觀察 | ✅ |

### 規格

```text
觸發：國家 N 的某座城被國家 C 攻下，且 N 因此一座城都不剩
效果：
  1. N 的所有部隊移除（不論在陸上、海上、或他國境內）
  2. N 名下剩餘的所有省份改歸 C
  3. N 退出戰局（不再有回合）
邊界：
  N 還有任何一座城 → 不投降，部隊與領土都不動
```

### 本專案

- 實作：`Session.captureProvince` → `Session.surrender`；`Session.ownsAnyCity`。
- 事件：`event_nation_surrendered`（「%1$s 向 %2$s 投降」）。
- 測試：`SessionTest` 的
  ``losing the last city is a surrender - units vanish, leftover land goes to the captor``、
  ``losing one of several cities is not a surrender``。
- 沒有城市、只剩部隊的國家（例如只有遠征軍的劇本勢力）不會因為這條規則出局；
  它們沿用舊規則：沒有任何省份也沒有任何部隊時才消失。

### UNKNOWN BEHAVIOR

1. **AI 對 AI 是否同樣適用。** 已確認攻方是玩家的 AI 盟軍時同樣投降（第 2 節）；
   攻守雙方都跟玩家無關的情況未直接觀察，本專案一視同仁，🟡。
2. **「領土」的範圍。** 原版的領土是城市轄下的格子；本專案的單位是省份，一省
   對應一座城。兩者在「最後一座城的領土歸攻方」這一點上結果相同。若原版還有不
   屬於任何城市的格子，那些格子投降後歸誰未知；本專案把投降國名下的所有省份都
   交給攻方。
3. **投降國的運輸艦上載著他國部隊時。** 本專案沿用「載具沉沒、乘客一起沉」的
   既有規則。原版未觀察。

## 4. 回合順序

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 開新局時由玩家先行動，AI 在玩家結束回合之後才行動 | 觀察 | ✅ |

### 規格

```text
每一輪：玩家 → 其他國家依序 → 回合數 +1 → 玩家 → …
第 1 回合開局時，任何 AI 都還沒有行動過。
```

### 本專案

- `Session` 建立時把玩家排在國家清單的第一位，其餘國家維持劇本檔的順序
  （依國力排），所以一輪總是從玩家開始。
- 國家 id 因此跟著玩家改變，存檔格式版本升到 2，舊版存檔視為過時。
- 測試：`SessionTest` 的 ``a new game starts on the player's turn, before any AI moves``。

### UNKNOWN BEHAVIOR

1. **AI 國家之間的先後順序。** 本專案依國力由強到弱。原版未觀察。

## 5. 佔領城市

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 城市沒有守軍、而且城市的 HP（城防）是 0，才能被佔領 | 觀察 | ✅ |

### 規格

```text
敵方或無主的城市 C，城防 hp(C)：
  hp(C) > 0  → C 對敵方是關著的：走不進、穿不過、空降落不下
               （可以從相鄰或射程內攻擊它的城防）
  hp(C) = 0 且 C 裡沒有部隊 → 第一支走進去的陸軍（能佔領的兵種）立刻拿下整省
```

### 本專案

- 實作：`Session.isCityShutTo`（走路、上岸、空降共用），`Orders.tryCapture`（進城即佔領）。
- 原本的「站在還有城防的空城裡，每回合削 50 點」圍城機制已移除：它讓部隊站在
  城裡、旗子卻還是對方的，跟「城防歸零才佔領」的規則看起來互相矛盾。
- 測試：`SessionTest` 的
  ``a city with defence left is shut until it is worn down, then taken by walking in``、
  ``nobody passes through a city that still has its defence``。

### 本專案的決定

打光城防的那一擊不會同時佔領：城防歸零之後，仍然要有一支能佔領的陸軍走進去。
原版是否如此未確認，但「要有人站進去才算佔下」是維護者要的規則。

## 6. 戰鬥傷害

### 觀察到的行為

| 行為 | 來源 | 狀態 |
|---|---|---|
| 一次攻擊的攻擊值在兵種的最小攻擊與最大攻擊之間均勻取整數（含兩端） | 逆向 | ✅ |
| 傷害 = 攻擊值 × 1000 / (防禦 × 16 + 1000)，整數除法；每 1 點防禦讓分母多 1.6% | 逆向 | ✅ |
| 攻擊值 = 固定加成 + ⌊攻擊% × 擲骰⌋；等級的加攻屬於固定加成，不受士氣與殘血影響 | 逆向 | ✅ |
| 攻擊% = 士氣（+1 → 125、0 → 100、−1 → 75、−2 → 50）× 編制 × 殘血門檻 | 逆向 | ✅ |
| 殘血門檻：HP 低於最大值的 50% 時攻擊% 減半；剛好 50% 不減 | 逆向、資料 | ✅ |
| 士氣 −3（混亂）不能反擊 | 逆向 | ✅ |
| 反擊與主動攻擊走同一條公式，不打折；反擊時用的是挨打之後的 HP | 逆向 | ✅ |
| 地形不替守方加防禦；只有攻方是裝甲或火炮時，依守方所在地形扣傷害 | 逆向、資料 | ✅ |
| 地形扣傷（裝甲 / 火炮）：沙漠 10/10、丘陵 10/5、山 20/10、樹林 5/10、森林 10/20，其他 0 | 資料 | ✅ |
| 守方所在城市的城防還在時，部隊只吃 0.5 倍（取代地形那一項），城防另外承受一份 | 逆向 | ✅ |
| 城防本身防禦 0：承受的是同一擲骰的攻擊值（不經防禦分母） | 逆向 | ✅ |
| 各步驟之間都是無條件捨去；最後的傷害最少 1 | 逆向 | ✅ |
| 編制 1–4：攻擊 100/125/150/175%，生命 100/160/210/250% | 資料 | ✅ |
| 等級每升一級：生命 +20、固定攻擊 +4、防禦 +2 | 資料 | ✅ |
| 最大 HP = 兵種 HP × 編制% + 等級加成（另有將領、科技等加成） | 逆向 | ✅ |
| 重算最大 HP 時，目前 HP 依比例縮放 | 逆向 | ✅ |
| 城防上限：小城市 150、中城市 300、大城市 450、大都市 600、首都 800 | 資料 | ✅ |
| 同規則的公式由維護者在原版實機比對過部隊面板的攻擊、防禦、HP，全部吻合 | 觀察 | ✅ |

### 規格

```text
擲骰    r ∈ [最小攻擊, 最大攻擊]，均勻整數
攻擊%   p = 士氣% × 編制% / 100 × (HP×100 < 最大HP×50 ? 50% : 100%)
攻擊值  v = 固定攻擊 + ⌊p/100 × r⌋
傷害    d = ⌊v × 1000 / (防禦 × 16 + 1000)⌋
        d = ⌊d × 其他倍率⌋
        d = ⌊d × (城防還在 ? 0.5 : 1 − 地形扣傷(守方格, 攻方兵種))⌋
        d = max(1, d)
城防    c = ⌊v × 其他倍率⌋，交火時 × 0.7（見 UNKNOWN 1），最少 1
交戰    攻方打一擊 → 守方活著且能還手 → 守方以挨打後的 HP 打一擊
```

例：攻擊 22、防禦 1 → 22 × 1000 / 1016 = 21；防禦 62.5 讓傷害減半；防禦 125 剩三分之一。

### 本專案

- 實作：`units/Combat.kt`（`hit`、`resolve`、`defended`、`attackPercent`、`terrainFactor`）；
  最大 HP 與編制、等級：`units/ArmyUnit.kt`（`maxHpFor`）；地形扣傷：`world/Terrain.kt`；
  城防上限：`world/Province.kt`（`maxCityHp`）。
- 兵種的攻擊範圍、HP、防禦取原版同類兵種的量級（例如步兵 16–22 / 80 / 1、中型戰車 28–44 / 180 / 10、
  驅逐艦 32–52 / 260 / 12），但兵種表是本專案自己的，不一一對應。
- **本專案保留的規則**，以乘數插在原版公式的對應位置：
  - 兵種相剋表（對步兵、裝甲、艦艇、飛機各一個百分比）—— 原版用兵種特性做類似的事。
  - 補給：攻擊% 乘補給係數；防禦乘 0.5 + 0.5 × 補給係數。
  - 科技與司令部光環：加在攻擊%；科技另外放大防禦。原版的科技是加固定點數。
  - 指揮官：攻方的傷害倍率、守方的減傷，位置相當於原版的將領技能。
  - 築壕：每級減傷 5%。
  - 浮渡中的陸軍：防禦 0、攻擊% × 0.3、多挨 50% 傷害、不能還手。原版的登船部隊防禦同樣是 0，
    多挨的傷害來自專打登船部隊的兵種特性；本專案把它簡化成一個固定倍率。
  - 打城牆的倍率取兵種「對步兵」與「對裝甲」較高的那一欄。
  - 經驗：依打掉對方最大 HP 的比例計算。原版的經驗規則未研究。
- **本專案沒有做的**：暴擊、穿甲、將領的固定攻擊與 HP 加成、首都 800（本專案的城市沒有首都等級，
  最高 600）、原版的等級 6（本專案最高 5 級）。
- 回血、斷補給失血、城防修復改成最大值的百分比（城裡 22%、野外 6%、斷補給 −8%、城防 5%）。
  這些是本專案的規則，原版沒有對應的補給機制。
- 移除：舊的「傷害 = 55 × 攻 / (攻 + 防)」比值公式、±8% 亂數、反擊六折、地形防禦加成、
  被貼身的火炮防禦 × 0.55。存檔格式升到 3 版，舊存檔視為過時。
- 測試：`CombatTest` 的
  ``each point of defence widens the divisor by 1_6 percent``、
  ``one hit follows the reference formula step by step``、
  ``a garrison with walls takes half and the walls take the roll undefended``、
  ``the counter is full strength but uses the defender's hp after the hit``、
  ``attack rolls are uniform integers between min and max``、
  ``max hp comes from kind, formation and level``、
  ``terrain hampers tanks and guns attacking into it, not infantry``。

### UNKNOWN BEHAVIOR

1. **城防分攤的 0.7。** 逆向結果確定城防那一份在某個條件下乘 0.7、否則乘 1。從呼叫端推測
   條件是「守方會還手」，但也有另一種讀法：「這一擊本身是反擊」。本專案採前者：守方會
   還手的交火（以及反擊本身）乘 0.7，打不還手的目標（遠程砲擊、空襲）整份。
   *實驗*：在原版用火炮從兩格外打一座有守軍的城，再用步兵貼身打同一座城，比較城防掉的量。
2. **升級時目前 HP 怎麼變。** 原版載入時依比例縮放；戰鬥中升級是否同樣處理未確認。
   本專案一律依比例縮放。
   *實驗*：讓一支殘血部隊在戰鬥中升級，記錄升級前後的 HP 與最大 HP。
3. **城防修復速度與易主後的城防。** 原版未研究；本專案維持自己的規則（每回合 5%、易主剩 35%）。
